Who this is for

This book is for the developer who was never taught the machine. You learned to program — variables, functions, maybe a lot of Rust — but nobody ever sat you down and explained what actually happens while a program waits. Threads were a box you were told not to open. Async was a keyword surrounded by rules you memorized. The kernel was weather: it did things, and you worked around it.

If Tokio’s documentation sometimes reads like a map in a language you only sort of recognize, the problem is not you — it is the missing prerequisites. This guide rebuilds them from scratch, bottom-up, in an order where nothing arrives before you can understand it.

The promise on every page: every term is defined before it is used. Registers before call stacks. File descriptors before epoll. poll before Pin. By the time we say the word runtime, you will already know exactly what needs runtime-ing — no hand-waving, no black boxes labeled “scheduler” and left sealed.

The only prerequisites are fluency in some programming language and patience for detail. You do not need a systems-programming background, prior Rust mastery (a one-page recap covers the parts async uses), or any networking knowledge. Examples lean on Rust, with cameos from C, JavaScript, and Python wherever a contrast teaches faster than a definition.

How to read this

Read it in order. The book is deliberately linear: Part 3 can build a Waker in your head only because Part 1 made readiness concrete, and Part 4 can open Tokio’s scheduler only because Part 3 built a miniature one. If you already know a topic, skim it — every page stands alone enough for that, and the sidebar always shows where you are.

Navigation is threefold: the sidebar holds the full table of contents, the footer of every page links to the previous and next pages with their part context, and the ← / → arrow keys do the same without a scroll.

The whole site is a folder of static files. It loads no webfonts, makes no requests, and highlights its code locally — download it, get on a plane, and read.

Where you’ll end up

Able to trace a single .await from your source, through the state machine the compiler built, onto Tokio’s run queue, down to an epoll_wait in the kernel — and back up when the waker fires. The last page assembles that full-circle mental model into one diagram. The bottom of the stack is the natural place to start: how a program runs.
