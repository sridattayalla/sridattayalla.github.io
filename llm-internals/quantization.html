Part Four — Inference at Scale

Quantization: int8 and int4

The serving page filled the card's idle arithmetic and left the floor standing: one full sweep of the weights per piece. This page shrinks the floor itself — the same weights, stored as small integers — and meets the two problems that make it hard: rounding noise, and a handful of channels that must not be rounded at all.

The lever: fewer bytes per weight

The decode floor is a division: weight bytes divided by memory bandwidth. The serving page amortized the numerator across requests. This page shrinks it. Quantization is storing the trained weights as small integers instead of sixteen-bit floats — the same network, in less memory — done after training, with no retraining [quantization].

The arithmetic of the lever, on the floor the loop page established [quantization]:

Worked example — the same sweep, smaller weights

the same sweep, smaller weights
(7B model, decode at one request):

  fp16 (2 bytes/param):   14e9 bytes -> 146 pieces/s ceiling
  int8 (1 byte/param):     7e9 bytes -> ~292 pieces/s
  int4 (0.5 bytes/param):  3.5e9 bytes -> ~584 pieces/s

  the arithmetic per step is unchanged — only the
  bytes moved. (requires kernels that restore the
  integers on the fly, inside the sweep)

Halve the bytes and the ceiling doubles; quarter them and it quadruples — the arithmetic per piece is untouched, only the bytes moved [quantization].

The panel's parenthetical is the engineering crux: the restoration happens inside the sweep. A quantized kernel never rebuilds the float matrix in memory — that would give the bytes right back. Instead, as each block of integers streams past on its way to the arithmetic units, the kernel multiplies by the group's scale in registers and feeds the result straight into the multiply-adds. The floats exist for nanoseconds, inside the chip, never in the card's memory at all.

Two cautions before the mechanism. First, this is a serving-time trick: training stays in mixed precision, as the GPU page accounted, and the integers are created afterward, once [quantization]. Second, the lever only pays in the bandwidth-bound phase: at large batch or long prefill, the step turns compute-bound and smaller weights buy almost nothing — the arithmetic still has to happen [quantization].

Scale and grid

How does a float become a small integer? Pick a scale factor — one number per group of weights — and divide. The result is rounded to the nearest integer on a grid of fixed size: sixteen levels for four-bit, two hundred fifty-six for eight-bit. Multiply the integer by the scale and the weight comes back, approximately [quantization].

One group, end to end [quantization]:

Worked example — one group of four weights, int4

one group of four weights, int4
(grid: integers -8..7, sixteen levels):

  weights w:        [ 0.62  -1.10   1.93  -0.44 ]
  scale s = max/7 =  1.93/7 ~ 0.28
  store q = round(w/s):
                     [  2     -4      7     -2  ]  (4 bits each)
  restore s * q:
                     [ 0.56  -1.12   1.96  -0.56 ]
  worst error: 0.12 (on the -0.44 weight)

  stored: 4 x 4-bit integers + one 16-bit scale
  was:    4 x 16-bit floats

Why groups? The scale must span the largest weight in whatever it covers. One scale for a whole matrix makes the grid coarse for every small weight in it; one scale per handful of weights — a hundred twenty-eight of them, in the common recipe — keeps each grid fine for its own neighborhood [quantization].

And the scale's own cost is thin. A hundred twenty-eight four-bit integers plus one sixteen-bit scale is five hundred twenty-eight bits for the group — an eighth of a bit per weight of overhead. The grouping buys fine grids almost for free.

Why does the rounding mostly not matter? A single restored weight can be off by a few percent, and a single wrong weight would matter. But a matrix multiply sums millions of terms per output — the errors are independent, some high some low, and they average toward nothing in the sum. Uniform rounding noise is mostly harmless at scale [quantization]. Mostly.

The exception: outliers

The "mostly" is doing work in that last sentence. Past roughly 6.7B parameters, trained models grow a small set of channels with outsized magnitudes — an outlier problem that appears as a phase transition, not a gradual drift: about a tenth of a percent of hidden dimensions, concentrated in roughly six channels in a 6.7B model [quantization].

These channels are load-bearing. Zeroing just those dimensions inflates perplexity by 600-1000%; rounding them to the eight-bit grid destroys quality just as thoroughly [quantization]. The noise-averaging argument fails here because the outlier channels are exactly where a few terms dominate the sum — their errors do not cancel, they propagate.

The fix keeps both worlds: mixed precision. LLM.int8(), the method that documented the outliers, computes those few channels in sixteen-bit floats and everything else in eight-bit integers — no measured quality loss at the 175B scale, roughly half the memory, and 175B-scale inference on far fewer GPUs [quantization].

Two recipes that ship

Outlier-aware mixed precision is one ingredient. Production int4 needed two more ideas, and they ship under their paper names. Both are weight-only quantization — the integers replace the weights, while the activations flowing through stay sixteen-bit — the common production recipe, with the cache sometimes following in eight-bit [quantization].

GPTQ compensates errors as it goes. It quantizes the weights one column at a time, and when a weight's rounding error is committed, it nudges the not-yet-quantized weights to cancel that error — using approximate second-order information about which weights matter, the lineage of an old pruning method called Optimal Brain Surgeon [quantization]. One pass, no retraining: a 175B model in about four GPU-hours, three-to-four-bit weights with negligible degradation [quantization].

AWQ protects instead of compensating. Its observation: about one percent of weight channels are salient — chosen by the size of the activations flowing through them, not by the size of the weights — and those channels must not absorb rounding error. The trick scales them up before quantization, shrinking their relative error, and folds the scaling into the activation side where it cancels exactly. No backprop, no retraining, and — the paper's point — it generalizes: code and math survive int4 where naive rounding breaks them [quantization].

Notice the symmetry with the outlier story. LLM.int8 found its trouble by watching activations blow up in a few hidden dimensions; AWQ finds its protected channels the same way — by activation magnitude, not weight magnitude. Two papers, two fixes, one lesson: the trained network concentrates its traffic in a few channels, and a compression scheme that cannot find and spare them breaks the model.

The one-percent protection, measured [quantization]:

Worked example — protecting one percent of channels

protecting one percent of channels
(OPT-6.7B, int4, group size 128;
WikiText2 perplexity):

  plain round-to-nearest int4:      43.2   (broken)
  + 1% salient channels kept
    at full precision:              13.0   (recovered)
  the fp16 original:                13.09

  salience measured by activation size,
  not weight size

At four bits, a 70B model fits a single 48 GB card, and runs about three times faster than the float original with proper kernels [quantization].

Where the lever stops

The lever has edges. Quantization error is not uniform across tasks: code generation and math degrade before chat does, because a single wrong piece breaks a program where prose forgives it [quantization]. Perplexity — the training page's measure — is a weak proxy here; teams evaluate real downstream tasks before shipping four-bit weights [quantization].

And the floor survives, smaller but standing: fewer bytes per piece, still one sweep per piece. The next page attacks the sweep itself — let a small model propose several pieces, and let the big model check them all in one pass.

Takeaways

  • Quantization stores trained weights as small integers plus scale factors — a post-training, serving-time change; halving bytes doubles the decode ceiling, quartering them quadruples it.
  • Divide by the scale, round onto the grid, restore by multiplying — per-group scales keep each grid fine for its neighborhood, and independent rounding errors average out across a matrix multiply's millions of terms.
  • Past ~6.7B parameters, a few outlier channels carry outsized magnitude — rounding or zeroing them wrecks quality; mixed precision keeps them in fp16 with no measured loss.
  • GPTQ compensates: each committed rounding error is pushed onto not-yet-quantized weights via second-order information. AWQ protects: ~1% salient channels, chosen by activation size, pre-scaled to shrink their relative error — perplexity 43.2 recovered to 13.0 on OPT-6.7B int4.
  • Weight-only int4 is the shipping recipe; the lever pays only in the bandwidth-bound phase — and one weight sweep per piece still remains, which the next page attacks.
