Start

The words the opening page needed before any mechanism existed.

memory safety
The guarantee that a program cannot read freed memory, write past an allocation, or race two threads on the same bytes — built into the language, not left to programmer care. Defined on the opening page.
garbage collector
A run-time component that periodically finds unreachable values and frees them; safe, but it charges pauses, bookkeeping overhead, and a permanent run-time presence. Defined on the opening page.
runtime
The machinery a language needs present while a program runs. Rust needs none for memory: freeing follows ownership, compiled into the program itself. Defined on the opening page.
ownership
Rust's answer to memory: every value has exactly one owner, and the value is destroyed when its owner is. Defined on the opening page.
owner
The variable or structure a value belongs to; the value's destruction follows the owner's. Defined on the opening page.
borrow checker
The compiler pass that enforces the rules of references — which may alias, which may mutate, and for how long — before the program ever runs. Defined on the opening page.
escape hatch
A marked, typed way out of a safety rule for programs the rule cannot express; honest when visible in the source. Defined on the opening page.

Part One — The Constraint

The cost list the constraint answers, and the two regions every value lives in.

stack
The region of memory holding call frames; local values live and die with the function call, at a speed the hardware makes free. Defined on The Constraint.
heap
The region for values that must outlive the scope that created them, change size, or be reached from more than one place. Defined on The Constraint.
dangling pointer
A pointer to memory that has already been freed; following it is a bug in most languages and a compile error in Rust. Defined on The Constraint.
use-after-free
Reading or writing memory after it was freed. Defined on The Constraint.
double free
Freeing the same allocation twice; the second free can corrupt the allocator's own bookkeeping. Defined on The Constraint.
iterator invalidation
Mutating a collection while holding a reference into it, leaving the reference aimed at moved or freed memory. Defined on The Constraint.
data race
Two threads touching the same memory at once with at least one writing; the outcome depends on timing. Defined on The Constraint.
undefined behavior
Behavior the language leaves unspecified; compilers may assume it never happens, which is what makes it dangerous. Defined on The Constraint.
sanitizer
A tool that instruments a compiled program to catch memory and threading errors at run time — the C world's partial answer to this book's cost list. Defined on The Constraint.
destructor
The code that runs when a value dies; in Rust, the drop routine. Defined on The Constraint.
deterministic destruction
Freeing at a known, compile-visible point — when the owner leaves scope — rather than whenever a collector gets around to it. Defined on The Constraint.

Part Two — Ownership

What it means to own a value, to hand it over, and to duplicate it.

move
Transferring ownership of a value to a new owner; the old binding cannot be used afterward. Defined on Ownership.
drop
Rust's destructor protocol: the routine a type defines for its own death, run automatically at scope end. Defined on Ownership.
scope
The region of a program in which a binding exists; scopes nest, and values die at the end of their owner's scope. Defined on Ownership.
RAII
Resource acquisition is initialization: tie a resource's lifetime to a value's, so cleanup runs by ownership rather than by hand. Defined on Ownership.
drop order
The fixed order values die at scope end: locals in reverse declaration order, fields in declaration order. Defined on Ownership.
trait
A contract: a named list of methods a type can promise to provide. Defined on Move, Copy, Clone.
copy trait
The opt-in marker for plain-data types that may be duplicated bit for bit instead of moved. Defined on Move, Copy, Clone.
clone
The trait for explicit, possibly deep duplication — what a call to .clone() runs. Defined on Move, Copy, Clone.
shallow copy
Duplicating a value's immediate bytes while sharing whatever they point to. Defined on Move, Copy, Clone.
deep copy
Duplicating a value and everything it reaches, so the copy shares nothing with the original. Defined on Move, Copy, Clone.

Part Three — Borrowing

Using a value without taking it — and proving the borrow ends in time.

reference
A borrowed pointer to a value the borrower does not own. Defined on Borrowing.
shared reference
An immutable borrow; any number may exist at once, and none may write. Defined on Borrowing.
mutable reference
An exclusive borrow; exactly one may exist, and it may write. Defined on Borrowing.
aliasing
More than one name reaching the same value at the same time. Defined on Borrowing.
aliasing xor mutability
The rule the borrow checker enforces: any number of shared references, or one mutable reference — never both at once. Defined on Borrowing.
borrowing
Taking a reference to a value without taking ownership; the borrower may not outlive what it borrowed. Defined on Borrowing.
lifetime
The span of a program in which a reference could be used; the compiler's proof that a borrow cannot outlive its value. Defined on Borrowing.
non-lexical lifetimes
The refinement that scopes borrows by actual use rather than by braces — a reference's lifetime ends at its last use. Defined on Borrowing.
NLL
Short for non-lexical lifetimes, the borrow analysis in use since it replaced the region-of-a-block reading. Defined on Borrowing.
lifetime elision
The default rules that let most functions omit lifetime annotations, filling in the common patterns automatically. Defined on Lifetimes.
region
The compiler's internal name for a lifetime: a set of program points, not a duration on a clock. Defined on Lifetimes.
outlives
Contains the entire lifetime of; the relation a borrow must satisfy with the value it points to. Defined on Lifetimes.
static lifetime
The region of the whole program; the bound that owned, borrowed-in data must satisfy to cross into a spawned thread. Defined on Lifetimes.

Part Four — The Heap Menu

The options once a value must leave the stack.

heap allocation
Requesting memory from the allocator at run time; the point where indirection and its costs enter the program. Defined on Stack and Heap.
slice
A borrowed view of a run of elements: pointer plus length, not an owner. Defined on Stack and Heap.
fat pointer
A pointer that carries its referent's missing information — a length for slices, a method table for trait values. Defined on Stack and Heap.
indirection
Reaching a value through its address instead of its name; the cost every heap handle pays. Defined on Box.
recursive type
A type that contains itself, such as a list node; it can exist only behind indirection, so the compiler can know its size. Defined on Box.
reference counting
Shared ownership via a count of live handles; the last handle to drop frees the value. Defined on Rc and Arc.
shared ownership
A value with many owners, none privileged; opted into explicitly, never the default. Defined on Rc and Arc.
reference cycle
Handles keeping each other's counts above zero forever; the leak reference counting cannot see. Defined on Rc and Arc.
weak reference
A handle that points without counting; it breaks cycles by not keeping the value alive. Defined on Rc and Arc.
atomic
An operation the hardware guarantees indivisible across threads; what a thread-safe count pays on every clone and drop. Defined on Rc and Arc.
memory leak
Memory never freed while the program runs; safe in Rust — no corruption — and reachable through cycles or deliberate leaks. Defined on Rc and Arc.

Part Five — Mutation and Threads

Changing and sharing at once, across threads.

interior mutability
Moving a mutation check from compile time to run time so a value can change behind a shared handle: Cell, RefCell, Mutex. Defined on Interior Mutability.
guard
The value a lock or run-time borrow returns; it holds the access and releases it by being dropped. Defined on Interior Mutability.
poisoning
A lock's decision to refuse further access after a holder died holding it — failure propagated instead of torn state. Defined on Interior Mutability.
Send
The marker trait saying a value is safe to move to another thread. Defined on Send and Sync.
Sync
The marker trait saying references to a value are safe to share across threads. Defined on Send and Sync.
marker trait
A trait with no methods, carrying only a compile-time fact. Defined on Send and Sync.
auto trait
A marker the compiler derives automatically from a type's fields. Defined on Send and Sync.
fearless concurrency
The promise that data races are compile errors, so concurrent code can be refactored without fear. Defined on Send and Sync.

Part Six — The Escape Hatches

The marked ways out — and the two tiers of failure they sit beside.

unsafe block
The marked region where a subset of checks is lifted and the programmer inherits their invariants by hand. Defined on Unsafe.
raw pointer
An untracked address — nullable, bound by no aliasing rules; following one is audited by the programmer. Defined on Unsafe.
soundness
The property that safe code cannot cause undefined behavior, no matter what the unsafe code inside it does. Defined on Unsafe.
safe abstraction
An unsafe implementation wrapped so its invariants cannot be broken from the outside. Defined on Unsafe.
pin
The wrapper that forbids moving a value after its address has been handed out. Defined on Pin.
pinning
The act of keeping a value at one address so its self-references stay valid. Defined on Pin.
self-referential
Containing pointers into itself; moving such a value would aim those pointers at stale addresses. Defined on Pin.
Unpin
The marker trait for types that are safe to move even when pinned — which is nearly every type. Defined on Pin.
future
A value representing a computation that may not have finished; it is polled forward until it completes. Defined on Pin.
async
The syntax for writing futures as if they were straight-line code; the machinery that needed pinning. Defined on Pin.
panic
The halting tier of failure: a broken invariant, unrecoverable by design. Defined on Errors and Panics.
unwinding
The panic-time walk up the stack that runs destructors on the way out. Defined on Errors and Panics.
propagation
Handing a failure upward to a caller who can decide; what the ? operator makes visible. Defined on Errors and Panics.
recoverable error
An expected failure carried as a value in a Result, handled by normal code. Defined on Errors and Panics.

Part Seven — Abstraction and Synthesis

Abstracting over types — and the whole language assembled into two programs.

coherence
The program-wide guarantee that any trait has at most one implementation for any type. Defined on Traits.
orphan rule
The rule that enforces coherence: an impl must own its trait or its type, or it cannot be written. Defined on Traits.
monomorphization
The compiler stamping out a specialized copy of generic code for every concrete type it is used with. Defined on Traits.
vtable
The per-type table of method addresses that a dynamic call reads. Defined on Traits.
trait object
A value typed only by what it can do — dyn Trait — reached through a fat pointer. Defined on Traits.
static dispatch
Call resolution at compile time: the exact function is baked into the call site. Defined on Traits.
dynamic dispatch
Call resolution at run time, through the method table of whatever value actually arrived. Defined on Traits.
newtype
A one-field wrapper that makes a foreign type local, satisfying the orphan rule at no run-time cost. Defined on Traits.
object safety
The set of trait shapes a trait object can actually serve — methods that need no hidden concrete type. Defined on Traits.
thread pool
A fixed set of worker threads created once, up front, and fed work from a queue — instead of one thread per task. Defined on the capstone.
