Part Four — The Heap Menu

Box: The One-Word Heap Pointer

The last page ended on the menu's smallest entry. A Box is one word — a single pointer to a heap cell — and it owns whatever sits in that cell: allocating is Box::new, freeing is the owner's death, and nothing about it is implicit. One word buys a fixed size, a heap address, and a clean transfer of ownership — this page is about what each of those costs and pays.

The one-word owner

The previous page sized it: a Box is one word, the same as a bare reference — the smallest owner in the language. Writing Box::new(value) allocates a heap cell, moves the value into it, and hands you the word that points there. When the box dies, the value in the cell dies with it and the cell is returned. There is no other machinery: no header on the cell, no count, no collector walking by.

What the word buys is worth naming, because the rest of the heap menu is built from it. An indirection is a pointer step between you and a value — one hop: you hold the address, the address holds the value. Inline values have none; a Box adds exactly one. That single hop is what keeps the allocation visible in the type: the reader of Box<String> sees one heap cell and one pointer step, and can price the line.

Notice what does not differ between Box<T> and &T: the size. Both are one word; both point at a T. What differs is the policy the word carries — the box owns its cell and frees it at death; the reference views a cell someone else owns and frees nothing. The word is the same shape; the responsibility is the type. That is the deepest habit of this language: size in the layout, policy in the type.

Why not box implicitly, as Java and Python do for nearly every object? Because implicit placement would hide exactly what this design exposes: the cost — an allocation and a pointer step on every access, invisible in the source — and the lifetime — a free that happens when the collector chooses, not at a named owner's death. The book's chapter on Box announces its subject plainly: "using Box<T> to point to data on the heap" — and the design reason is the one this book keeps repeating: visible cost, deterministic free.[memory-layout]

Moving a Box moves the value

A Box is an owner, so everything Part Two said about owners applies unchanged. It is not Copy: assigning or passing it moves it, and the move hands over the allocation — the new owner's word points at the same cell, and the free happens at the last owner's death, exactly once.

One behavior is unique to Box. It is the only owner on the menu whose value you can move out by dereferencing:

The line let s = *b; walks the pointer, lifts the whole String — its words and its buffer — out of the cell, and leaves the box holding nothing. The empty cell is freed when b leaves scope; the String dies wherever s dies. No other owner on the menu allows this: moving a value out of a dereference would leave the owner unable to honor what it still owes. Box owes exactly one thing — free the cell — and that duty stays provable after the value leaves.[memory-layout]

The type that contains itself

The need for the one-word owner shows up the moment a type wants to contain itself. A linked list is the classic: a node is either the end of the list, or a value plus the rest of the list — and the rest of the list is another node. Written out directly:

Read the error's language: recursive without indirection. A recursive type is a type whose definition contains a value of that same type — Cons(i32, List) qualifies. Rust sizes every type before the program runs: a fixed number of bytes, computed eagerly from the definition. A List containing a List containing a List without end has no finite size, and the compiler says so at the definition itself — has infinite size — rather than at any use.

The comparison explains why this error surprises programmers arriving from the other languages. In Java, a field of type Node is already a reference — the pointer step is implicit in every field, so class Node { Node next; } compiles, and every node is a separate heap object. In C, the same type is written with the step showing — struct Node { struct Node *next; } — because a value that contains itself by value has no size in any of these languages. Rust lands with C and goes further: the step is written, visible, and counted, and the checker proves the chain it builds is freed.[memory-layout]

This is the only recursion error Rust has. There is no lazy sizing, no runtime-resizable type slot, no tagged-union escape hatch with a size decided later: the size of every type is settled at compile time, and the fix is always the same shape — insert a pointer step. The help line names the candidates: insert some indirection (e.g., a Box, Rc, or &). This page's candidate is the one-word one.[memory-layout]

One word breaks the cycle

The fix works because of the size fact from the last page: a Box is one word no matter what it points at. Box<List> is a pointer — a fixed, finite size — regardless of how big a List is. The regress stops: each node holds an integer, one pointer word, and nothing else.

Stated and run, with the destructuring match doing double duty as the ownership demonstration:

Two ownership facts are visible in that run. The outer match l consumes the list — each arm takes its node by value, because matching an owner moves into the arms. And match *rest dereferences the inner box to keep matching: the tail's value lifts out of its cell, the cell dies at the scope's end, and the chain unwinds node by node as the arms finish. Ownership transfer, indirection, and deterministic free — one program, all three, and no collector anywhere near it.[memory-layout]

Beyond one word

One word is not always the whole story, and the last page named the exception: a reference to a value reached through a trait is a fat pointer — two words, the address plus the pointer to the trait implementations. The boxed version has the same shape: a Box holding such a value is also a fat pointer, two words, with the same second word doing the same job. The traits part of this book owns what that second word calls and how; the fact this page needs is only its size.[memory-layout]

Box has exactly one owner; graphs want many. Rust makes that an explicit, typed decision — the next page.

Takeaways

  • A Box is one word — a heap pointer that owns its cell: Box::new allocates, the owner's death frees, nothing implicit anywhere.
  • Indirection is one pointer step between you and the value; Box adds exactly one, and the type shows where.
  • Box is the only owner you can move a value out of by dereferencing — its single duty, freeing the cell, stays provable after the value leaves.
  • A recursive type contains itself; Rust sizes every type eagerly at compile time, so the definition without a pointer step has no finite size — E0072 names it.
  • Box<List> breaks the cycle: one word regardless of contents, and the chain ends where the last pointer says Nil.
